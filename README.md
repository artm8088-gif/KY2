# Dependency Visualizer (Вариант 2)

Инструмент для визуализации графа зависимостей пакетов формата **npm** (JavaScript).
Разрабатывается в рамках курсовой работы по дисциплине НИАСПО.

## Требования
- Python 3.10+
- Git

## Параметры командной строки

- `--package` — имя анализируемого пакета (обязательный).
- `--repo` — URL репозитория (GitHub/GitLab) или путь к файлу (обязательный).
- `--test-mode` — режим работы с локальным тестовым репозиторием (файлом).
- `--output` — имя сгенерированного файла с изображением графа (по умолчанию `graph.svg`).
- `--ascii-tree` — режим вывода зависимостей в формате ASCII-дерева.

## Реализованные этапы

### Этап 1. Минимальный прототип с конфигурацией
Создано минимальное CLI-приложение на Python. 
На данном этапе реализован разбор аргументов командной строки с помощью модуля `argparse`, а также настраиваемые параметры (имя пакета, URL/путь к репозиторию, режим тестирования, имя выходного файла, флаг ASCII-дерева). 
При запуске приложение выводит все переданные параметры в формате ключ-значение. Также реализована полная валидация всех входных данных: обработка пустых значений, проверка корректности URL, проверка существования локальных файлов и прав на запись. При возникновении ошибок программа выводит понятное сообщение в `stderr` и завершается с ненулевым кодом возврата.

### Этап 2. Сбор данных
Реализована основная логика получения информации о прямых зависимостях пакета. 
В соответствии с требованиями, запрещено использование менеджеров пакетов (`npm`, `yarn`) и сторонних библиотек. Поэтому для скачивания и парсинга используется исключительно стандартная библиотека Python (`urllib` и `json`).

**Что именно сделано:**
- Написан модуль, который по URL-адресу репозитория GitHub или GitLab автоматически формирует прямую ссылку на сырой файл `package.json` и скачивает его.
- Реализован режим `--test-mode`, позволяющий читать `package.json` из локального файла (без обращения к сети).
- Написан парсер, который извлекает информацию исключительно из секции `dependencies` (прямые зависимости), игнорируя `devDependencies` и другие служебные поля.
- Реализован вывод на экран имени пакета, его версии и отсортированного по алфавиту списка всех прямых зависимостей.
- Добавлена обработка ошибок сети (таймауты, HTTP 404, сбои SSL) и ошибок формата данных (некорректный JSON, отсутствие нужных полей).
- Для проверки работы без интернета создан тестовый файл-фикстура, имитирующий реальный `package.json`.

**### Этап 3. Построение транзитивного графа зависимостей**

Реализовано построение полного транзитивного графа зависимостей пакетов с использованием алгоритма поиска в ширину (BFS). В отличие от предыдущего этапа, приложение теперь собирает не только прямые зависимости исходного пакета, но и зависимости всех обнаруженных пакетов.

**Что именно сделано:**

- Реализован алгоритм BFS с использованием очереди `deque` из стандартной библиотеки Python. Обход выполняется без рекурсии.
- Добавлено построение графа, в котором вершины представляют пакеты, а рёбра — связи между пакетами и их прямыми зависимостями.
- Реализован обход транзитивных зависимостей: алгоритм последовательно обрабатывает найденные пакеты и добавляет их зависимости в граф.
- Добавлены множества `visited` и `scheduled` для предотвращения повторной обработки пакетов и повторного добавления пакетов в очередь.
- Предусмотрена корректная обработка циклических зависимостей, исключающая бесконечный обход графа.
- Расширен тестовый режим `--test-mode`: реализовано чтение и проверка локального JSON-файла, описывающего несколько пакетов и связи между ними.
- Добавлена валидация структуры тестового репозитория, имён пакетов и описаний зависимостей.
- Реализован вывод графа в текстовом формате с общим количеством пакетов и связей, а также отсортированными списками зависимостей и их версий.
- Добавлен вывод зависимостей в формате ASCII-дерева с отображением структуры вложенности и пометками обнаруженных циклов.
- Проведено тестирование на нескольких наборах данных, включая граф с общими зависимостями и циклическими связями, а также проверена работа с данными из npm Registry.
