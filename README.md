## Описание проекта

**Dependency Visualizer** — консольное приложение на Python для анализа зависимостей npm-пакетов и построения графа их взаимосвязей.

Программа получает информацию о зависимостях выбранного пакета, анализирует прямые и транзитивные зависимости, обрабатывает циклические связи и формирует визуальное представление графа.

Результаты работы можно получить в нескольких форматах:

- Текстовый список зависимостей.
- ASCII-дерево зависимостей.
- Граф в формате Mermaid.
- Изображение графа в формате SVG.
- Порядок загрузки зависимостей.

Также предусмотрена возможность сравнения построенного графа с деревом зависимостей, полученным с помощью npm.

## Требования

Для работы приложения необходимы:

- Python 3.10 или выше.
- Git.
- Node.js и npm — для дополнительного режима сравнения с реальным деревом зависимостей npm.
- Установленные Python-зависимости из `requirements.txt`.

## Параметры командной строки

| Параметр | Описание |
|---|---|
| `--package` | Имя анализируемого npm-пакета. Обязательный параметр. |
| `--repo` | URL репозитория или путь к локальному тестовому файлу. Обязательный параметр. |
| `--test-mode` | Включает режим работы с локальным тестовым репозиторием. |
| `--output` | Имя выходного SVG-файла. По умолчанию `graph.svg`. |
| `--ascii-tree` | Включает вывод зависимостей в формате ASCII-дерева. |
| `--load-order` | Выводит порядок загрузки зависимостей. |
| `--compare-npm` | Включает дополнительное сравнение с деревом зависимостей npm, если данный параметр реализован в основном CLI. |

Все переданные параметры конфигурации выводятся в формате `ключ=значение`.

## Реализованные этапы

### Этап 1. Минимальный прототип с конфигурацией

Создано минимальное CLI-приложение на Python.

На данном этапе реализовано:

- Разбор аргументов командной строки с помощью `argparse`.
- Настройка параметров: имя пакета, URL или путь к репозиторию, режим тестирования, имя выходного файла и режим ASCII-дерева.
- Вывод параметров конфигурации в формате ключ-значение.
- Валидация входных данных.
- Проверка пустых значений и корректности URL.
- Проверка существования локальных файлов.
- Проверка корректности имени выходного файла и возможности его записи.
- Обработка ошибок с выводом понятных сообщений в `stderr`.
- Завершение программы с ненулевым кодом возврата при возникновении ошибок.

### Этап 2. Сбор данных

Реализована логика получения информации о прямых зависимостях npm-пакетов.

Для получения и обработки данных используется стандартная библиотека Python, включая `urllib` и `json`.

Реализовано:

- Получение информации о пакете из указанного репозитория GitHub или GitLab через файл `package.json`.
- Формирование ссылки на сырой файл `package.json`.
- Загрузка и чтение локального `package.json` в режиме `--test-mode`.
- Парсинг секции `dependencies`.
- Игнорирование `devDependencies` и других служебных полей.
- Получение имени пакета, его версии и списка прямых зависимостей.
- Сортировка зависимостей по алфавиту.
- Обработка ошибок сети, HTTP-ошибок и некорректного JSON.
- Создание тестовой фикстуры для проверки работы без подключения к интернету.

### Этап 3. Построение транзитивного графа зависимостей

Реализовано построение полного транзитивного графа зависимостей с использованием алгоритма поиска в ширину — **BFS (Breadth-First Search)**.

В отличие от предыдущего этапа, программа анализирует не только прямые зависимости исходного пакета, но и зависимости всех обнаруженных пакетов.

Реализовано:

- Использование очереди `deque` из стандартной библиотеки Python.
- Итеративный обход графа без рекурсии.
- Построение графа, в котором вершины представляют пакеты, а рёбра — зависимости между ними.
- Последовательная обработка транзитивных зависимостей.
- Использование множеств `visited` и `scheduled` для предотвращения повторной обработки пакетов.
- Обработка циклических зависимостей без бесконечного обхода.
- Расширение тестового режима для работы с несколькими пакетами и связями между ними.
- Валидация структуры тестового JSON-файла, имён пакетов и описаний зависимостей.
- Вывод общего количества пакетов и связей.
- Вывод отсортированных списков зависимостей и их версий.
- Построение ASCII-дерева с отображением вложенности и обнаруженных циклов.
- Проверка работы на графах с общими зависимостями и циклическими связями.
- Проверка получения данных из npm Registry.

### Этап 4. Порядок загрузки зависимостей

Добавлена возможность определения порядка загрузки пакетов с помощью параметра `--load-order`.

Для определения порядка используется алгоритм топологической сортировки — алгоритм Кана.

Реализовано:

- Построение порядка обработки пакетов на основе связей графа.
- Использование количества входящих связей для определения последовательности обработки.
- Вывод зависимостей в порядке, при котором необходимые пакеты располагаются раньше зависящих от них пакетов.
- Обработка графов с циклическими зависимостями.
- Вывод ошибки, если граф невозможно упорядочить топологической сортировкой.
- Проверка алгоритма на тестовых графах с различной структурой зависимостей.
- Сравнение полученного порядка с порядком, используемым npm.

**Особенности сравнения:**

Порядок топологической сортировки показывает допустимую последовательность обработки зависимостей с учётом связей графа. Реальный npm может использовать другую последовательность установки и разрешения зависимостей, поэтому результаты не обязательно совпадают.

### Этап 5. Визуализация графа зависимостей

Реализована визуализация построенного графа с использованием Mermaid и сохранением результата в формате SVG.

Реализовано:

- Преобразование структуры графа в синтаксис Mermaid.
- Создание вершин для пакетов и рёбер для связей между ними.
- Генерация уникальных идентификаторов узлов.
- Стабильная сортировка элементов для получения воспроизводимого результата.
- Сохранение исходного описания графа в формате `.mmd`.
- Рендеринг графа в изображение `.svg` с использованием `mermaidx`.
- Обработка ошибок генерации и сохранения изображения.
- Проверка визуализации на нескольких npm-пакетах.
- Дополнительное сравнение с деревом зависимостей, полученным через npm.

**Сравнение с npm:**

Для сравнения используется отдельный модуль `npm_visualization.py`, который получает дерево установленных зависимостей с помощью команды `npm ls --all --json`.

Полученное дерево преобразуется в Mermaid и сохраняется в форматах JSON, MMD и SVG.

Результаты могут отличаться от графа основной программы по следующим причинам:

- Основная программа анализирует зависимости по метаданным пакетов.
- npm разрешает конкретные версии зависимостей.
- npm учитывает особенности установки, включая вложенные зависимости.
- На результат могут влиять peer dependencies и optional dependencies.
- Различия в версиях пакетов могут приводить к различной структуре графа.

Таким образом, сравнение позволяет оценить различия между графом зависимостей, построенным по метаданным, и фактически установленным деревом npm.

## Структура проекта

```text
Dependency-Visualizer/
│
├── src/
│   ├── __init__.py
│   ├── main.py
│   ├── cli.py
│   ├── graph.py
│   ├── visualization.py
│   └── npm_visualization.py
│
├── tests/
│   └── test_program.py
│
├── requirements.txt
├── README.md
```

Назначение основных модулей:

| Модуль | Назначение |
|---|---|
| `main.py` | Основная точка входа и объединение компонентов приложения. |
| `cli.py` | Разбор и проверка параметров командной строки. |
| `graph.py` | Получение данных, построение графа, BFS и топологическая сортировка. |
| `visualization.py` | Генерация Mermaid и сохранение SVG. |
| `npm_visualization.py` | Получение и визуализация дерева зависимостей через npm для сравнения. |
| `test_program.py` | Автоматические тесты основных компонентов программы. |

## Примеры запуска

**Построение графа для пакета axios:**

```bash
python -m src.main --package axios --repo https://registry.npmjs.org --output axios.svg
```

**Построение графа с выводом ASCII-дерева:**

```bash
python -m src.main --package axios --repo https://registry.npmjs.org --ascii-tree --output axios.svg
```

**Вывод порядка загрузки зависимостей:**

```bash
python -m src.main --package axios --repo https://registry.npmjs.org --load-order
```

**Работа с локальным тестовым репозиторием:**

```bash
python -m src.main --package A --repo tests/test_repository.json --test-mode --ascii-tree
```

**Дополнительное сравнение с npm:**

```bash
python -m src.npm_visualization --package axios
```

Аналогичные проверки визуализации можно выполнить для пакетов `mime-types` и `webpack`.

## Тестирование

Для запуска автоматических тестов используется `pytest`.

Установка:

```bash
python -m pip install pytest
```

Запуск всех тестов:

```bash
python -m pytest -v
```

Запуск отдельного файла тестов:

```bash
python -m pytest tests/test_program.py -v
```

Проверяются:

- Корректность разбора параметров CLI.
- Обработка некорректных входных данных.
- Чтение и проверка JSON-файлов.
- Построение графа зависимостей.
- Обход графа алгоритмом BFS.
- Обработка циклических зависимостей.
- Вычисление порядка загрузки.
- Генерация Mermaid.
- Сохранение SVG-файлов.
